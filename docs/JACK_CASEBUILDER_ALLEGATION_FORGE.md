# JACK THE RIPPER — CASEBUILDER / ALLEGATION FORGE

Jack is the case-construction subsystem inside APEX.

Prime directive:

> TURN EVERY MATERIAL EVENT INTO A PROPOSITION THAT CAN BE PROVEN, ATTACKED, STRENGTHENED, AND USED.

## Ownership

- APEX control plane: proof-bound state, schemas, receipts.
- Mastermind: dispatch/composition.
- AKOS: knowledge construction and epistemic state.
- computer-user: connector/file execution and acquisition.
- case repositories: source-specific case state.

## Graph

`CASE -> INCIDENT -> EVENT -> ACTOR -> FACT -> SOURCE -> ALLEGATION -> ELEMENT -> CONTRADICTION -> HARM -> DEFENSE -> DISCOVERY -> REMEDY`

No material allegation may exist only as loose prose.

## Promotion

`RAW -> STRUCTURED -> SOURCED -> CORROBORATED -> ELEMENT_MAPPED -> DEFENSE_TESTED -> HARDENED -> PLEADING_READY -> REFERRAL_READY -> TRIAL_READY`

Promotion is evidence-bound.

## Occurrence-first rule

Unknown identity never erases supported conduct. Create a Doe actor object and an identity-acquisition target.

## Hardening

Draft -> attack facts -> attack sources -> attack elements -> attack attribution -> attack mental state -> attack causation -> attack damages -> build best defense -> rebut -> identify gap -> acquire proof -> rewrite -> attack again.

## Source law

Native/original source outranks derivative summary. Contradictory sources remain preserved until resolved.

## Mental state

Contradiction is not automatic fraud or intent. Knowledge and intent require separate evidentiary construction.

## Required outputs

MASTER_FACT_LEDGER, MASTER_EVENT_TIMELINE, ACTOR_INDEX, ALLEGATION_LEDGER, ELEMENT_MATRICES, CONTRADICTION_MATRIX, EVIDENCE_MATRIX, DAMAGES_LEDGER, DISCOVERY_MATRIX, DEFENSE_MATRIX, ACCOUNTABILITY_MATRIX, PLEADING_MAP, REFERRAL_MAP, QUARANTINE_LEDGER, EXECUTION_RECEIPTS.

The runtime implementation is `src/jack_casebuilder.py`.
