# Context-first, power-preserving execution contract

**Recover before creating. Continue before reconstructing. Compound before replacing.**

This is a repository-local operating contract for humans and agents. It does not imply ChatGPT automatically loads this file, that any PR is merged, or that a provider effect occurred.

## Mandatory order
1. Identify the current mission from the current request. Recover its existing decisions, source records, prior branches, PRs, open work, execution cursor, corrections, and governing architecture before selecting a change.
2. Read the current default branch and all relevant existing branches and open PRs. Map unique capabilities, overlaps, dependencies, conflicts, merged work, and regressions. **Never equate branch count with capability count.**
3. Define the desired outcome and its real-world proof. Reuse and extend the canonical owning subsystem; do not create a parallel implementation when an existing one can be repaired or composed.
4. Preserve every stronger verified behavior and unique source-linked improvement. Integrate cumulatively; reject changes that silently remove safeguards, evidence, case coverage, or test coverage.
5. Execute authorized work, not just analysis or task creation. For external/legal effects, require independent authorization, exact case/mission/source binding, durable idempotency, native provider receipts, and readback. Drafts, labels, comments, and commits are not filings or execution receipts.
6. Run targeted regression tests and relevant integration tests. Compare against baseline, investigate failures, and distinguish tests not run from tests passed.
7. Read back the actual repository/provider state, preserve exact receipts and continuation cursor, and keep going until the execution frontier or a real blocker is reached.

## Branch convergence
- Canonical default branch is the integration target, not a reason to discard unmerged work.
- Audit before merge or deletion; recover unique capabilities, source provenance, and tests from every relevant branch.
- Prefer additive, reviewed, conflict-aware convergence. Do not blindly merge or delete branches.
- Report what is merged, merely committed, tested, runtime-verified, and externally executed **separately**.

## Anti-regression questions
What existed before? What stronger capability could this change strand or weaken? What other branch implements this already? What evidence would falsify success? What exact native receipt proves the outcome? What remains unresolved?

## Failure rule
If context cannot be recovered, identify the exact missing source and pursue the appropriate acquisition route. Do not pretend the source was recovered; do not globally stop unrelated independent work. Never manufacture accomplishment or claim automatic boot from repository code alone.
